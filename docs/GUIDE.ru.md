# Kolorit — руководство

**Kolorit** перекрашивает изображения в заданную палитру и добавляет ретро-эффекты.
Краткое знакомство — в [README](../README.md), английская версия руководства — в [GUIDE.md](GUIDE.md).

Название — от слова «колорит»: приложение переносит изображение в нужный колорит палитры
и придаёт ему колорит старой видеокассеты.

## Что умеет

### Перекраска в палитру
Каждый пиксель заменяется ближайшим цветом палитры в выбранной цветовой модели:

| Модель | Как сравниваются цвета | Когда брать и чего ждать |
|--------|------------------------|--------------------------|
| RGB    | евклидово расстояние между каналами | ровнее всех держит яркость; лучший выбор для палитр из чистых цветов (ZX Spectrum) и для тонированных ч/б палитр вроде Game Boy. Переоценивает синий: он даёт треть расстояния при 7 % вклада в яркость |
| HSL    | биконус: оттенок — угол, хрома — радиус, светлота — высота | хрома весит вдвое больше светлоты, поэтому цвет сохраняется точнее, а тона упрощаются сильнее. Хороша для цветастых палитр, непригодна для палитр из оттенков серого |
| HSV    | конус: радиус — насыщенность×яркость, высота — максимальный канал | то же, что HSL, но «яркость» — это max(R,G,B), поэтому насыщенный синий стоит на одной высоте с белым и тени высветляются. Не для серых палитр |
| XYZ    | CIE XYZ, D65 — линейный свет | шаг в светах весит примерно в восемь раз больше такого же шага в тенях, поэтому света детальны, а тени схлопываются. Скорее художественный приём, чем точность |
| **CIE Lab** | перцептивно равномерное пространство, ΔE76 | обычно лучший результат для фотографий: расстояние соответствует видимой разнице цветов, палитра используется полнее. На тонированных ч/б палитрах (Game Boy) теряет светлые тона — там берите RGB |

Модель решает тем больше, чем сильнее палитра «чужая» изображению. Если палитра снята с самого снимка
(k-средних), разница между RGB, HSL и Lab укладывается в единицы процентов — заметно отстаёт только XYZ.

Дизеринг: без дизеринга; упорядоченный — Байер 2×2 / 4×4 / 8×8 и **синий шум** (с регулируемой силой);
диффузия ошибки — **Флойд–Стейнберг, Аткинсон, Сьерра, Стукки, Джарвис–Джудис–Нинке**.
Синий шум считается так же параллельно, как Байер, но клетки не даёт: пороги расставлены алгоритмом
«пустот и скоплений», поэтому в спектре нет низких частот и узор рассыпается в ровную крупу.
Аткинсон рассеивает лишь 6/8 ошибки — картинка контрастнее, вид классического Macintosh.
Диффузия идёт змейкой: чётные строки слева направо, нечётные справа налево, и на обратном ходу ядро
зеркалится — иначе ошибка всё время сносится вправо и оставляет наклонный след.
У Байера каждый канал берёт узор со своей фазой, поэтому дизеринг передаёт не только полутона яркости,
но и промежуточные оттенки; пороги зависят только от младших битов координат, поэтому считаются один раз
в таблицу 8×8×3 (768 байт, целиком в L1), а не на каждый пиксель; общий на три канала порог остался в эффекте «Ретро-консоль», где яркостная
клетка и есть нужный вид.
У диффузии ошибки накопленная невязка ограничена ±96 единицами на канал: если нужного цвета в палитре нет вовсе
(цветной снимок в палитре из оттенков серого), ошибка иначе растёт без предела и разваливает картинку.

### Палитры
* Загрузка из файла: PNG N×1 или любое изображение — берутся все его уникальные цвета.
* Сохранение в PNG N×1.
* **Панель палитры**: добавление цвета через диалог, изменение по двойному клику, удаление (Delete),
  сортировка по яркости / оттенку, перестановка перетаскиванием. Под кнопкой «⋯» — операции над
  палитрой целиком: **упорядочить как градиент** (соседями становятся самые близкие цвета —
  для градиентной карты и дуотона; на сжатом RAL сумма переходов падает с 1011 до 602),
  **сжать до N цветов** (k-средние по самой палитре: RAL из 213 цветов превращается в рабочие 16,
  и ошибка выходит 12,1 против 14,8 у равномерной выборки) и **добавить палитру из файла**.
* Встроенные палитры зашиты в код (`core/BuiltinPalettes`) и разложены по разделам меню, чтобы список
  не растягивался на весь экран:
  * **Лестницы и градиенты** — цвета идут строго от теней к светам, то есть годятся для
    градиентной карты и дуотона, где порядок палитры и есть форма градиента: перцептивно равномерные
    шкалы viridis, magma, inferno, plasma, cividis (рассчитана на дейтеранопию) и turbo, а также
    классические фотографические тонирования — сепия, цианотипия, платинотипия, селен.
  * **Ретро-платформы** — NES / Денди, ZX Spectrum, Game Boy и Game Boy Pocket, Commodore 64,
    IBM CGA (16 цветов и две канонические четвёрки режима 4), IBM EGA (64) и Amstrad CPC (27) —
    это ровные решётки по каналам, поэтому считаются, а не хранятся, — MSX 1 / TMS9918,
    Macintosh System. Значения взяты из общепринятых реконструкций: точных чисел у большинства
    машин не существует, цвет рождался в аналоговом тракте.
  * **Пиксель-арт** — авторские наборы: PICO-8, DawnBringer 16 и 32, Sweetie 16, Endesga 32.
    Их собирали художники так, чтобы цвета сочетались и на каждый оттенок хватало теней и светов,
    поэтому на фотографиях они заметно связнее аппаратных палитр того же размера: по ΔE2000 на тестовом
    изображении Sweetie 16 (10,63) обходит не только CGA и Macintosh на тех же 16 цветах (16,06 и 16,38),
    но и NES на 54 цветах (13,13) и EGA на 64 (11,69); Endesga 32 даёт 8,77. Взяты наборы, которые авторы
    выложили в свободное использование — условия у каждого свои.
  * **Интерфейсы и темы** — Solarized, Nord, Gruvbox, Dracula, Catppuccin Mocha,
    Material Design (тона 500) и Tailwind CSS (оттенки 500): подогнать снимок под фирменный стиль
    или под оформление сайта.
  * **Программы и печать** — Gartic Phone, MS Paint, RAL Classic, web-safe (216, по формуле),
    «Радуга» (360 оттенков).
* **Создать палитру** — один диалог вместо пяти пунктов меню: тип выбирается списком,
  поля меняются под него, полоска внизу показывает результат сразу.
  * **Оттенки серого** — от 2 до 256 уровней, с галочкой «равные ступени на глаз»: равный шаг по
    светлоте L* вместо равного шага в байтах, самая заметная ступень короче на 12–17 %.
  * **Тон одного цвета** — лестница выбранного оттенка во всю глубину тона (насыщенность спадает
    к чёрному и белому). Своё «под Game Boy» любого цвета, и, в отличие от аппаратной палитры,
    такая лестница не вырождается в два цвета.
  * **Растяжка между цветами** — два цвета или три, интерполяция в CIE Lab; готовая лестница
    для градиентной карты и дуотона.
  * **Уровни на канал** — все сочетания равномерных уровней: 3 — палитра Amstrad CPC, 4 — EGA, 6 — web-safe.
  * **Круг оттенков** — оттенки по кругу при одинаковой светлоте и насыщенности; ровная замена
    «Радуге», у которой светлота гуляет на 19 единиц L*.
* **На основе изображения (чанки)** — сетка X×Y, средний цвет каждой ячейки, с живым предпросмотром.
* **k-средних** — k наиболее характерных цветов изображения. Кластеризация идёт в **CIE Lab**,
  поэтому цвета палитры распределяются так, как их различает глаз, а не по «сырым» каналам RGB
  (в RGB синий даёт треть расстояния при 7 % яркости, и кластеры перекашивает в его сторону).
  Инициализация k-means++, параллельный шаг назначения, прореживание выборки до 2 млн точек.
* **Уникальные цвета изображения**.
* **С другого изображения** — палитра снимается k-средними с файла-образца и применяется
  к открытому снимку: приём «сделай этот кадр в колорите того».
* Текущая палитра запоминается между запусками.

### Эффекты
* Инверсия, оттенки серого, сепия, постеризация, пикселизация, коррекция цвета
  (яркость / контраст / насыщенность) — все с живым предпросмотром.
* **Градиентная карта** — яркость пикселя превращается в положение на градиенте из цветов
  текущей палитры (первый цвет — тени, последний — света): тонирование, «тепловая карта», основа дуотона.
  Плавные переходы или ступени, обратный порядок, баланс средних тонов, сила смешивания с исходником.
* **Дуотон / тритон** — два цвета (тени и света) или три (плюс средние тона) выбираются прямо
  в диалоге, баланс и сила смешивания; классика печати и постеров.
* **Уровни** — точки чёрного и белого, гамма средних тонов, выходной диапазон и отдельные
  сдвиги точки чёрного по каналам, которыми правят паразитный оттенок в тенях. В отличие от коррекции
  цвета, где есть только яркость, контраст и насыщенность, здесь управляют формой всей кривой.
* **Выделение цвета** — выбранный диапазон оттенков остаётся цветным, остальное уходит в серое.
  Диапазон считается по кругу, поэтому красный на стыке 0°/360° не разрывается; порог насыщенности
  не даёт зацепить почти серые пиксели.
* **Газетный растр** — изображение разбирается на печатные точки переменного размера. При
  цветоделении каждая краска CMYK получает свой угол сетки, как в офсете: точки складываются в розетку
  и не дают муара. Есть и одна чёрная краска, и печать светлым по тёмному.
* **Таблица цветов (.cube)** — 3D LUT формата, общего для DaVinci Resolve, Premiere и Photoshop:
  готовые плёночные грейды применяются прямо в Kolorit, значения между узлами считаются трилинейной
  интерполяцией (читаются и одномерные таблицы). Обратно: **«Сохранить .cube из результата»** прогоняет
  последнюю операцию по цветовому кубу 33³ и записывает её как LUT — перекраску в палитру можно унести
  в видеоредактор.
* **Удаление артефактов** — билатеральный фильтр (радиус, порог различия цветов, число проходов)
  сглаживает шум, зерно и артефакты сжатия JPEG, не размывая контуры; опциональный медианный фильтр
  убирает точечный шум.
* **Пиксель-арт** — укрупнение пикселей с усреднением, квантование цветов (уровни на канал
  или текущая палитра в выбранной цветовой модели) и обводка контуров: тёмная линия рисуется по краю
  более тёмного из двух соседних блоков, толщина — доля «пикселя», порог контраста и тёмность настраиваются.
  Палитру и цветовую модель можно менять на панелях, не закрывая диалог, — предпросмотр обновится сам;
  при квантовании в палитру поле «уровней на канал» отключается.
* **Ретро-консоль** — Game Boy (зелёный / Pocket), NES / Денди, ZX Spectrum: уменьшение до
  разрешения консоли, квантование в её аппаратную палитру с дизерингом Байера, честные ограничения
  (Game Boy — 4 уровня яркости; NES — 4 цвета на блок 16×16; Spectrum — 2 цвета одной яркости на знакоместо
  8×8, «атрибутный конфликт»), увеличение обратно чёткими пикселями или целочисленно с полями.
  Палитры консолей есть и во встроенных.
* **ЭЛТ-телевизор** — выпуклый экран кинескопа с закруглёнными углами и рамкой, расхождение
  цветов, свечение ярких участков (bloom), маска люминофора (апертурная решётка / теневая / щелевая),
  строки развёртки, виньетка, блик на стекле, усиление яркости. В связке с «Ретро-консолью» даёт
  картинку со старого телевизора.
* **Диск** — изображение обрезается по кругу и ложится на CD/DVD: отверстие и ступица
  (прозрачный пластик с кольцами и фаской, тёмный «механизм» с канавками, спицами и акцентным кольцом
  в тон картинке, или печать до центра), прозрачный ободок и фаска по краю, объёмное затенение,
  дифракционная радуга с тонкими лучами и глянцевый блик под выбранным углом света, дорожки, мягкая тень
  на полях; масштаб и сдвиг картинки внутри диска; вокруг — прозрачность (или тёмный фон).
* **VHS-камера**:
  * хроматическая аберрация изображения: **фильтр левого и правого слоя** (красный, зелёный, синий, жёлтый,
    пурпурный, голубой) и смещение в пикселях;
  * такая же независимая аберрация для текста;
  * растекание цвета (горизонтальное размытие цветности при резкой яркости — как на аналоговом видео);
  * плавное дрожание строк с редкими разрывами, полоса помех (tracking) с настраиваемым положением,
    высотой и сдвигом;
  * строки развёртки (период, толщина, затемнение), зерно, виньетка;
  * цветокоррекция;
  * экранные надписи шрифтом VT323 в духе видеокамер: время в 12-часовом формате (`PM 1:02`), дата (`FEB 21 2023`), своя строка,
    индикатор `PLAY ▶` / `● REC` / `PAUSE`, выбор угла, размера и цвета текста, текущее или заданное время;
  * seed случайности — результат воспроизводим;
  * живой предпросмотр на уменьшенной копии, полный расчёт по кнопке «Применить»;
  * параметры сохраняются между запусками.

### Интерфейс
* **Одна верхняя панель** без строки меню: открыть, вставить, сохранить | исходник (сравнение),
  вернуть оригинал | отмена (во время обработки) … «Эффекты ▾» и «⋯» (тема, язык,
  панели, о программе, выход). Каждое действие есть ровно в одном месте: перекраска — на панели «Перекраска»,
  работа с палитрой — на панели «Палитра», масштаб — кнопка в статус-баре.
* **Язык**: английский или русский; по умолчанию — как в системе, сменить можно в «⋯ → Язык»
  (программа предложит перезапуск).
* **Обновления**: при запуске Kolorit в фоне спрашивает GitHub, не вышла ли новая версия, и если вышла —
  предлагает скачать её (файл откроется в браузере) или пропустить эту версию. Если новостей нет или нет
  сети, ничего не показывается. «⋯ → Проверить обновления…» проверяет вручную, а «⋯ → Проверять
  обновления при запуске» отключает автоматическую проверку.
* **Темы**: тёмная (по умолчанию), светлая и системная — «⋯ → Тема», переключаются на лету.
  Стиль Fusion с собственной палитрой и акцентным цветом; векторные монохромные иконки перекрашиваются
  под тему и чётко рисуются при любом DPI.
* **Боковые панели**: «Перекраска» (цветовая модель и дизеринг с подсказками, кнопка основного действия,
  пояснение, почему она недоступна) и «Палитра» (полоска-превью, сетка образцов, редактирование,
  сортировка, загрузка/сохранение, создание из изображения и встроенные палитры). Панели можно
  перетаскивать, отстёгивать и скрывать.
* **Пустое состояние**: без изображения область просмотра показывает, что делать; пустая палитра —
  откуда её взять.
* Во время обработки поверх картинки — надпись с прогрессом; в статус-баре — подсказка о следующем шаге,
  сведения о файле, число потоков и кнопка масштаба с быстрыми значениями.
* Все подсказки содержат горячие клавиши.

### Наборы настроек
У диалогов эффектов сверху появилась одна строка: список сохранённых наборов, «Сохранить…» и «Удалить».
Набор запоминается под именем в настройках пользователя и восстанавливается одним выбором из списка.
Подключены постеризация, пикселизация, коррекция цвета, градиентная карта, дуотон, удаление артефактов,
пиксель-арт, ретро-консоль, ЭЛТ и диск.

### Пакетный режим
Рядом с `Kolorit.exe` собирается `kolorit-cli.exe` — та же перекраска, но без окна и над списком файлов
или целой папкой:

```bash
kolorit-cli --palette "Sweetie 16" --model lab --dither floyd --out Results Images
```

`--palette` принимает и путь к PNG N×1, и имя встроенной палитры; `--model` — `rgb|hsl|hsv|xyz|lab`;
`--dither` — `none|bayer2|bayer4|bayer8|bluenoise|floyd|atkinson|sierra|stucki|jarvis`; есть ещё
`--strength` и `--format`. Полный список — `kolorit-cli --help`.

Утилита всегда говорит по-английски и принимает английские имена встроенных палитр — их выводит
`kolorit-cli --list-palettes`. Так скрипты работают одинаково при любом языке системы.

Отдельный исполняемый файл нужен из-за подсистемы Windows: `Kolorit.exe` собран как оконный (WIN32),
у такого нет консоли — вывод уходил бы в никуда, а оболочка не дожидалась бы завершения. На macOS утилита
лежит внутри бандла и использует его библиотеки Qt: `/Applications/Kolorit.app/Contents/MacOS/kolorit-cli`.

### Живой предпросмотр
Диалоги эффектов **немодальные**: пока подбираются параметры, главное окно остаётся живым — картинку можно
масштабировать колесом, перетаскивать, вписывать в окно (Ctrl+0) или смотреть 1:1 (Ctrl+1), а Ctrl+B
переключает на исходник для сравнения. Предпросмотр двухступенчатый: при каждом изменении параметра
сразу считается быстрый кадр на уменьшенной копии, а после короткой паузы — тот же эффект в полном
разрешении, чтобы при увеличении были видны настоящие детали. Кадр любого разрешения показывается
в координатах полного изображения, поэтому масштаб и положение не прыгают. Если полноразмерный кадр
уже готов, кнопка «Применить» использует его без пересчёта.

### Работа с изображениями
* Открытие файла (Ctrl+O), вставка из буфера обмена (Ctrl+V), **перетаскивание файла в окно**, аргумент командной строки.
* **Цветовой профиль файла** — если в снимке есть встроенный профиль (Display P3 у телефонов,
  AdobeRGB у зеркалок), цвета приводятся к sRGB при загрузке, и в строке состояния написано, из какого
  профиля. Вся обработка считает цвета значениями sRGB — и линеаризация, и переводы в XYZ и Lab, и веса
  яркости, — поэтому без этого картинка уезжала ещё до начала перекраски.
* Сохранение результата (Ctrl+S) в PNG / JPEG / BMP / WebP.
* Просмотр с масштабированием колесом, панорамированием, «вписать в окно» (Ctrl+0) и 100 % (Ctrl+1), двойной клик переключает.
* Переключение «исходник / результат» (Ctrl+B).
* **История операций** — панель справа, как в Photoshop: список шагов сверху вниз, нулевой —
  открытый файл. Каждая законченная операция сама становится шагом и текущим изображением, поэтому
  цепочка строится без лишних нажатий. Щелчок по строке возвращает изображение к этому шагу; шаги ниже
  текущего показаны блёклыми — они ещё доступны, но пропадут, как только поверх ляжет новая операция.
  Ctrl+Z — шаг назад, Ctrl+Y или Ctrl+Shift+Z — вперёд, F12 — к нулевому шагу.

  Хранятся не снимки изображения, а сами операции: картинка любого шага получается прогоном цепочки
  от исходника. Поэтому глубина истории почти ничего не стоит по памяти (два десятка снимков 12 Мп
  заняли бы под гигабайт) и поднята до 64 шагов. Плата — время: возврат назад пересчитывает цепочку
  и потому идёт в фоне, с прогрессом и отменой по Esc. Цепочка из десяти операций пересчитывается
  за 35 мс на 1,1 Мп и за 306 мс на 9,7 Мп. Шаг вперёд считается от текущего изображения, то есть
  стоит ровно одну операцию.
* Рядом с exe (на macOS — в `~/Documents/Kolorit`) создаются каталоги `Images/`, `Results/`, `Palette/` —
  их по умолчанию открывают диалоги файлов.

## Многопоточность

Вся обработка выполняется на всех ядрах процессора:

* Каждая операция — `ImageOp` (`std::function<QImage(const QImage&, QPromise<QImage>&)>`), запускаемая
  через `ImageTaskRunner` в отдельном потоке-оркестраторе, чтобы интерфейс никогда не блокировался.
* Внутри операции `parallelRows()` раскладывает строки изображения по глобальному `QThreadPool`
  (`QtConcurrent::blockingMap` с адаптивным размером блоков). Строки пишутся напрямую в память
  результата (`RowWriter`), без `detach()` и без блокировок.
* Прогресс — через `QPromise::setProgressValue`, отмена — через `QPromise::isCanceled()` перед каждой строкой (Esc в окне).
* Случайность в VHS детерминирована по `hash(seed, номер строки)`, поэтому результат не зависит от числа потоков.
* Поиск ближайшего цвета палитры кэшируется (атомарные ячейки, 512 КБ) — повторяющиеся цвета
  обходятся одним чтением из памяти. Ключ — цвет, огрублённый до 6 бит на канал: кэш на все
  16,7 млн значений RGB занимал 32 МБ, и его обнуление стоило ≈4,6 мс на каждую операцию
  независимо от размера картинки. По замерам огрубление не меняет результат (ΔE2000 расходится
  не больше чем на 0,02 при пороге заметности около 1), зато перекраска ускорилась вдвое-втрое,
  а на 16 потоках — впятеро.
* Число потоков регулируется в статус-баре; по умолчанию — число ядер.
* Единственный последовательный проход — диффузия ошибки (по природе алгоритма); она тоже
  выполняется в фоне с прогрессом и отменой.

Автономный тест печатает время каждой операции в один поток и во все (`kolorit_selftest`).

## Сборка

Готовые сборки для Windows и macOS лежат на странице [Releases](https://github.com/Kalikoff/Kolorit/releases).
Workflow Build собирает и тестирует обе платформы на каждый push; если отправить тег вида `v1.0.1`,
он ещё и опубликует релиз с архивом для Windows и образом диска для macOS.

Нужны CMake 3.21+, Qt 6.10+ (Core, Gui, Widgets, Concurrent, Svg, Network, LinguistTools; для WebP — дополнение
Image Formats) и компилятор с C++20 (MSVC 2022+, GCC 11+, Clang 14+). Kolorit собирается и проверяется
на Windows и macOS 13+.

Пресеты ищут Qt по переменной окружения `QTDIR`. Можно вместо этого передать
`-DCMAKE_PREFIX_PATH=<путь к Qt>` или завести свои пресеты в `CMakeUserPresets.json`.

**Windows**, Visual Studio 2022 или 2026:

```bat
set QTDIR=C:\Qt\6.10.2\msvc2022_64
cmake --preset vs2022
cmake --build --preset vs2022-release
```

Ninja (из *Developer Command Prompt for VS*):

```bat
cmake --preset ninja-release
cmake --build --preset ninja-release
```

**macOS**: нужны Xcode Command Line Tools (`xcode-select --install`), CMake и Ninja:

```bash
export QTDIR=~/Qt/6.10.2/macos
cmake --preset ninja-release
cmake --build --preset ninja-release
```

С `-DCMAKE_OSX_ARCHITECTURES="arm64;x86_64"` на шаге конфигурации получится универсальная сборка
для Apple Silicon и Intel — так собирается релиз.

Исполняемые файлы: `build/<preset>/bin/`. На Windows для запуска из каталога сборки в `PATH` должен быть
`<Qt>/bin`; либо соберите переносимую версию с библиотеками, плагинами и переводами Qt
(префикс должен быть абсолютным путём):

```bat
cmake --install build/vs2022 --config Release --prefix %CD%\dist
```

На macOS установка даёт `dist/Kolorit.app` с фреймворками Qt, `kolorit-cli` внутри бандла и ad hoc
подписью, без которой приложение не запустится на Apple Silicon:

```bash
cmake --install build/ninja-release --prefix "$PWD/dist"
```

Тесты:

```bat
ctest --preset vs2022-release
```

```bash
ctest --preset ninja-release
```

* `kolorit_selftest <изображение|-> <каталог>` прогоняет все операции ядра в 1 и в N потоков,
  сравнивает результаты, печатает время и сохраняет PNG.
* `kolorit_uitest <изображение|-> <каталог>` offscreen создаёт главное окно и диалоги, выполняет
  перекраску и эффекты, ходит по истории, проверяет русский перевод и сохраняет снимки.

Вместо пути к изображению можно передать `-` — тесты сами сгенерируют тестовую картинку
(`tests/TestImage.h`), внешние файлы им не нужны.

**Переводы.** Исходный язык — английский; русские строки лежат в `translations/kolorit_ru.ts`
и встраиваются в приложение при сборке. После правки строк интерфейса обновите файл командой
`cmake --build <build> --target update_translations` и переведите новые строки в Qt Linguist.

**Картинки документации** рисует `tools/readme_images.cpp` из фотографий в `docs/images/photos`:

```bat
cmake -B build/vs2022 -DKOLORIT_BUILD_TOOLS=ON
cmake --build build/vs2022 --config Release --target readme_images
```
